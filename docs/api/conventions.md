# Параметры, ошибки и повторы API

Это короткая карта существующих соглашений. Конкретный маршрут и его
request/response в [OpenAPI](../../openapi.json) или MCP `tools/list` остаются
обязательной проверкой перед интеграцией. Семейства API не имеют единого
формата ошибки, способа пагинации или политики повторов.

## Списки и фильтры

| Пример | Что проверено |
| --- | --- |
| `GET /api/v1/products?page=1&limit=5` | `page` начинается с 1, `limit` допустим от 1 до 100; вне диапазона — `400`. По умолчанию `page=1`, `limit=20`. Ответ содержит `items` и `meta` (`total`, `page`, `limit`, `pages`). См. [роутер](../../routers/api_products.py) и [проверку диапазона](../../services/product_read_service.py). |
| `GET /api/v1/filters/config` | Конфигурация фильтров для витрины; параметры конкретного поиска смотрите в `GET /api/v1/products` в схеме. Не подставляйте произвольные имена фильтров. |
| `GET /api/manager/products/{product_id}/supplier-offer-candidates` | Внутренняя Manager-операция: `supplier_id` обязателен, `page ≥ 1`, `limit` от 1 до 100, по умолчанию 50; см. [роутер](../../routers/manager_supplier_mapping.py). |

Некоторые Manager-списки вообще не принимают `page/limit`, другие имеют
эти параметры. Для новых Manager-списков правило проекта — `limit ≤ 100`,
но два существующих маршрута поставок принимают до 200: анализ источника
`GET /api/manager/supplier-sources/{source_id}/analysis` и кандидаты импорта
`GET /api/manager/supplier-offers/source-url-import-candidates`. У второго
`total` означает число возвращённых кандидатов, а не весь объём поиска.
Ограничения проверяйте у конкретной операции; нельзя добавлять `page` к любому
URL по аналогии. Проверьте параметры и
response model выбранной операции. Даже если OpenAPI показывает `page`/`limit`
публичного каталога как обычные integer без диапазона, фактический сервис
проверяет его отдельно; это известный пробел схемы, а не другое правило API.

## Ошибки и повторы

| Поверхность | Форма / действие клиента |
| --- | --- |
| Публичная витрина | Ошибки шлюза/маршрута обычно имеют `detail`; непойманная ошибка — `message`. `401` может означать неверный host или подпись до обработки тела. Подробности — [контракт витрины](../storefront-context-contract.md#resolution-and-compatibility). |
| Manager | Контролируемые бизнес-ошибки и ошибки валидации используют `detail: {message, error_code, field_errors}` ([handler](../../core/app_http.py), [helper](../../core/manager_api_errors.py)). Другие `HTTPException`, например некоторые ошибки авторизации, могут иметь строковый `detail`; клиент не должен предполагать одну форму для всех статусов. |
| MCP | Ошибка инструмента приходит как `isError` и structured `error` внутри MCP-результата; успешный HTTP-ответ транспорта сам по себе не доказывает успешную бизнес-команду ([код](../../services/connector_mcp.py), [handoff](../chatgpt-connector-handoff.md#повторы-ошибки-и-восстановление)). |

Для входа Manager отдельная защита может вернуть `429` и `Retry-After`
([auth.py](../../routers/auth.py)); похожие лимиты встречаются у отдельных
операций. Общий rate limit для всего API здесь не обещается. Читайте
`Retry-After`, когда он возвращён, и не обходите `403`/`409` новой попыткой
без разрешения причины.

`POST /api/v1/orders` и публичные Lead intake поддерживают
`Idempotency-Key`: подписанные записи обязаны передать один корректный ключ.
Повтор с тем же ключом и содержанием возвращает сохранённый результат,
изменение содержимого с тем же ключом — `409`; занятость может дать `503` с
`Retry-After: 1`. Точные границы, срок хранения receipt и условия для
канонического unsigned клиента —
[контракт публичной записи](../storefront-context-contract.md#public-write-idempotency).
Для существующих unsigned клиентов есть совместимость, но при отсутствии
ключа сервер создаёт новый внутренний ключ: это не даёт клиенту надёжного
повтора потерянного ответа ([код](../../core/public_write_idempotency.py)).

В первом MCP все изменения требуют `idempotency_key`; изменение существующей
записи дополнительно требует `expected_version`. После timeout повторяют
тот же payload и ключ; при конфликте версии сначала перечитывают запись
([контракт](../chatgpt-connector.md#повторные-запросы-и-исходное-время)).
Эти правила не распространяются автоматически на все старые Manager-мутации
или будущую интеграцию поставщиков.
