# Universal Feature Library v1

## Статус

Это эталон, а не команда немедленно создать все 20 записей в production. Реестр используется для проверки новых Feature, консолидации дублей и последовательного наполнения каталога.

Полные описания, aliases и возможные правила находятся в [`data/features/universal_v1.json`](../../data/features/universal_v1.json).

## Правила развития библиотеки

- Новый canonical slug добавляется только после проверки aliases и существующих брендовых Feature.
- Брендовое название сначала рассматривается как alias или override канонической Feature.
- Отдельная брендовая Feature допустима, если у неё есть отличающийся механизм и самостоятельная покупательская польза.
- Автоматическое правило опирается только на нормализованный spec key и проходит тест на реальных значениях. `derived` остаётся источником итоговой projection, а не scope Feature.
- Пороговые правила, например «тихо», зависят от типа оборудования и не должны применяться ко всему каталогу одним числом.
- Изменение смысла, категории или aliases требует обновления JSON, документации и governance-тестов в одном PR.

## TCL canary: аудит и исправления

Аудит исходного `data/feature_canary/tcl_2026.json` выявил:

1. `heating-minus-20` и `heating-minus-25` были отнесены к «Производительности» и плодили сущности для каждого порога. Они заменены одной derived Feature `low-temperature-heating` в категории `heating`; точная температура остаётся характеристикой модели.
2. `vstroennyi-wi-fi` и `wifi-ready` были универсальными по смыслу, но ограничены `brand_slug=tcl`. Ограничение снято; назначение остаётся derived по `wifi_state`.
3. `bipoliarnyi-ionizator` и `uf-sterilizatsiia` ошибочно описывались как TCL-only. Они переведены в universal, а применимость по-прежнему задаётся ссылкой серии.
4. `smart-inverter-tcl` дублировал `inverter-control` без отдельной покупательской пользы. Запись помечена неактивной, старые series links удаляются canary-сервисом, заменой служит `inverter-control`.
5. `FreshIN+`, `QuadriPuri` и `Gentle Breeze` остаются брендовыми: у них есть подтверждённый отдельный механизм и понятная польза.
6. `Индикатор качества воздуха` остаётся более узкой TCL Feature до отдельного решения о консолидации с каноническим «Контролем качества воздуха»: индикатор не равен автоматическому управлению по датчику.

Миграция категорий исправляет текущие данные безопасно. Canary после деплоя следует сначала запустить в dry-run, затем отдельно с `--execute` после просмотра отчёта.
