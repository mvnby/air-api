# Адресное применение сверки с прайсами: задача 1190

Этот план заменяет для будущего исполнения предложение на 149 классификаций
из [первого аудита](catalog-decision-source-audit-1190.md). Старый manifest
сохраняет прежний digest и объём; запускать его вместо нового плана нельзя.
Предыдущие 34 исправления не повторяются.

## Согласованный объём

После пересмотра приоритета источников пользователь согласовал точные
`kind-proposals.json` и `technical-proposals.json` из частного реестра.
Их SHA закреплены в
[отдельном manifest](../config/catalog_source_repairs/catalog-decision-1190-price.json).
Это разрешение на перечисленные значения; дрейф данных не разрешает заменять
их новым автоматически расширенным планом.

| Действие | Объём |
| --- | ---: |
| `other` → `complete_split_system` | 167 карточек |
| Адресные технические значения | 319 путей на 67 из этих карточек |
| Номинал: каноническое, основное и типизированное значения | 45 карточек |
| Исправление кириллической С на латинскую C в модели внутреннего блока | 35 карточек |
| Состав, питание и потребление Chigo | 4 карточки |
| Зимний комплект точной модификации WS30/WS40 | 38 карточек |

Технические группы пересекаются. Из 319 путей 137 относятся к типизированным
зеркалам; остальные 182 — к самим значениям. Меняются только отдельные ключи,
а не все спецификации. Остальные typed-поля и диапазоны сохраняются.

Первичен свежий прайс поставщика на точный продаваемый SKU. Для комплектности
проверены состав и положительная цена системы. Реальные различия суффиксов
не нормализуются. Исправления алфавита заданы по ID и точному составу прайса,
без глобального нечёткого сопоставления моделей.

Номиналы копируются из явной ячейки kW точной модификации. Для зимних вариантов
они могут существенно отличаться от базовой модели: №556 — 7.0 kW, №559 —
7.2 kW. Эти значения показаны в согласованном реестре; подмена мощностью базовой
модели не входит в операцию. Для Hisense заполняются только восемь отсутствующих
номиналов: 1212–1215, 1217, 1219, 1222, 1225. Валюта не выводится из слова «руб.».

## Исключения

- **5 блокеров:** 188, 189, 191 — конфликт привязок; 1004, 1005 —
  неоднозначный наружный SKU `HN1(-L)`. Ни kind, ни мощность №191 не меняются.
- **42 отложенные позиции:** нет однозначного текущего предложения. Наличие
  неизвестно; это не подтверждённое отсутствие на складе. Карточки, публикация,
  slug, URL и остальные данные сохраняются.
- **3 отдельных внутренних блока:** 1080, 1082, 1084 остаются исключёнными.
- **33 Hisense:** не определён код валюты; 10 ранее замеченных расхождений
  масштаба суммы остаются вопросами к данным. Цены и валюта не меняются.
- №195: цена подтверждает продажу системы, но точные обозначения двух блоков
  остаются вопросом; технических исправлений этих обозначений нет.

Цены, остатки, предложения, mappings, настройки источников и права не входят
в операцию. Отдельный существующий сбой Wi-Fi-фильтров `builtin`/`none`
не исправляется этой сверкой и не считается успешной проверкой данных.

## Выполнение

Действуют [production data gates](production-data-operations.md) и
[правила выпуска](deployment.md#verification). Код выполняется из точного
выпущенного образа на проверенном primary под каноническим `.deploy.lock`.
Сам merge или выпуск инструмента ещё не подтверждает применение данных.

1. Снова прочитать ограниченные диапазоны 15 ответов прайсов из частного
   source ledger. Проверить точные пары, технические ячейки и отсутствие
   изменений бизнес-значений относительно согласованных предложений.
2. Сохранить свежий план из выпущенного образа:

   ```bash
   python scripts/repair_catalog_decision_prices.py > /tmp/catalog1190-price-reviewed.json
   ```

3. Сверить 167 ID, 319 путей, 50 исключений и хеши двух согласованных файлов.
   Подтверждение пользователя уже относится к этому точному предложению.
   Свежий digest фиксирует проверенное отсутствие дрейфа, а не расширяет объём.
4. Под deployment lock передать этот JSON и его `plan_digest`:

   ```bash
   python scripts/repair_catalog_decision_prices.py \
     --execute \
     --reviewed-plan /tmp/catalog1190-price-reviewed.json \
     --execute-plan-digest REVIEWED_SHA256 \
     --confirm-manual-kind-review-digest REVIEWED_SHA256
   ```

План действует 30 минут. Identity, полные specs, цены и коммерческое состояние
всех 217 карточек защищены хешами. В транзакции блокируются родители, карточки,
категории, связи, источники, предложения и локальные остатки. Наблюдательные
timestamps polling нейтральны; бизнес-значения защищены. Смешанное либо частично
применённое состояние блокирует весь batch. Перед commit проверяются точные
целевые значения и strict eligibility всех 167 систем. Изменения, catalog
revision и outbox фиксируются атомарно; любая ошибка до commit откатывает их.

## Приёмка и откат

После применения сохранить полный read-only снимок и сверить все 217 карточек:
только 167 видов и 319 перечисленных путей отличаются от исходного состояния.
50 исключений, цены, остатки и привязки должны совпадать. Старый инструмент
34 правок должен возвращать ноль изменений.

Проверить strict eligibility, количество до пагинации, список и snapshots
подбора, явные форму/мощность/температуру/наличие и сортировку. Обязательны
`/api/health`, `/api/v1/products?limit=5`, `/api/v1/filters/config`.
Свежий dry-run нового инструмента должен вернуть ноль. Исполнение такого
no-op плана не создаёт новую revision или outbox.

При дрейфе остановиться до записи и сохранить отчёт; не обновлять guard-хеши
вручную для обхода проверки. Для отмены уже зафиксированной операции нужен
отдельный точный reviewed reverse plan с проверкой свежего состояния.
Общая переклассификация, повтор старых 34 правок и восстановление всей JSON
карточки из старого снимка не являются откатом.

Локальные проверки: unit-тесты новой политики и прежнего manifest, PostgreSQL
тесты атомарности, rollback, исключений и no-op, а также профильные тесты
подбора и импорта. PostgreSQL использует отдельную физическую тестовую БД
по [процедуре тестов](development-workflow.md#backend-tests).
