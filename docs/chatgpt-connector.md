# Kitlane: личное подключение ChatGPT

Первый выпуск предоставляет отдельную авторизацию и ограниченный MCP-контракт.
ChatGPT интерпретирует запрос пользователя, а Kitlane проверяет доступ,
сохраняет данные и возвращает результат. Backend не вызывает LLM.

## Возможности

| Действие | Результат |
| --- | --- |
| Найти клиента или заказ | Короткий список доступных записей, ID и ссылка в Manager |
| Сохранить обращение из текста, расшифровки голоса или изображения | Входящее обращение с исходным текстом, извлечёнными полями и списком недостающих данных |
| Найти/исправить входящее | Текущее обращение и версия, обновление по ожидаемой версии |
| Создать поручение | Постоянная запись с автором, исполнителем, необязательными сроком/напоминанием и проверенными связями |
| Показать поручения | Активные, на сегодня, просроченные, без даты, завершённые или отменённые |
| Изменить, завершить или открыть поручение снова | Изменение с проверкой актуальной версии |

Неполные обращения сохраняются для проверки. Желаемая дата клиента не бронирует
монтаж и не подтверждает свободное время. Разбор изображений и голоса происходит
на стороне ChatGPT; сервер принимает текст и факты. В этом выпуске нет отправки
писем/сообщений, автоматических фоновых действий или изменения заказов.

## Адрес и доступ

- MCP: `https://api.mvn.by/api/connector/mcp` (Streamable HTTP, stateless JSON).
- Issuer: `https://api.mvn.by`.
- Resource metadata: `https://api.mvn.by/.well-known/oauth-protected-resource`.
- OAuth metadata: `https://api.mvn.by/.well-known/oauth-authorization-server`.
- Предопределённый публичный клиент: `kitlane-chatgpt`; client secret отсутствует.
- Authorization code с PKCE S256; `resource` должен совпадать с MCP URL целиком.
- Callback по умолчанию: `https://chatgpt.com/connector_platform_oauth_redirect`.
- Обязательный scope `kitlane:read`; отдельно разрешаются
  `kitlane:incoming:write` и `kitlane:tasks:write`.

Callback должен оставаться в явно настроенном списке. Не добавлять произвольные
URL, динамическую регистрацию клиента или перенаправления из запроса.
Токены непрозрачные; сервер хранит их хеши и привязывает доступ к конкретной
учётной записи, членству, компании и storefront. Каждая HTTP-операция и каждый
tool call повторно проверяют действующий доступ. Отключение пользователя,
изменение учётных данных/роли/членства или отзыв подключения прекращают доступ,
включая обращения после MCP initialization.

## Подключение в личном аккаунте

После развёртывания backend открыть ChatGPT Plugins, добавить custom MCP server
по адресу выше, выбрать OAuth и указать `kitlane-chatgpt` как predefined client
ID без секрета. Войти своей именной учётной записью Kitlane и разрешить нужные
scopes. Доступность этой функции проверяется в самом аккаунте пользователя.

Страница подтверждения разрешает браузеру возврат только к зарегистрированному
callback. Каждая открытая форма имеет отдельный одноразовый CSRF-токен,
привязанный к сессии Manager; подтверждение доступно в течение 10 минут.
После ошибки на уже отправленной форме начать подключение заново из ChatGPT,
чтобы получить новое подтверждение.

Пакет находится в [plugins/kitlane](../plugins/kitlane/plugin.json): portable
`plugin.json`, `mcp.json`, ограниченный skill и локальный каталог
`.agents/plugins/marketplace.json`. Пути каталога разрешаются относительно корня
пакета, поэтому `source.path` равен `./`. Пакет не содержит токенов или секретов.
Для локального каталога зарегистрировать `plugins/kitlane` через
`codex plugin marketplace add ./plugins/kitlane`, затем перезапустить desktop
app и выбрать источник Kitlane. Personal installation не означает публичную
публикацию в каталоге OpenAI.

Регистрация локального каталога проверяет пакет. OAuth первого выпуска настроен
для callback ChatGPT; подключение из Codex потребует отдельно зарегистрированного
клиента и разрешённого callback, поэтому эта команда не подтверждает его работу.

Если ChatGPT требует registered MCP mapping, сначала создать сервер через
Plugins, получить реальный `plugin_asdk_app...` ID и добавить mapping `.app.json`
в пакет с `extensions.com.openai.apps`. Такой ID назначается аккаунтом и не
включён в репозиторий заранее. Не подставлять фиктивный ID.

Отозвать подключение можно в Manager, в разделе подключений ChatGPT. После
отзыва повторный tool call должен потребовать новое подключение. Отключение
плагина в ChatGPT не заменяет отзыв серверного grant.

## Повторные запросы и исходное время

Каждое изменение требует `idempotency_key`. Одинаковый ключ и неизменённый
payload возвращают прежний результат с `replayed=true`; другой payload с тем же
ключом вызывает конфликт. После timeout следует повторять тот же запрос,
поскольку первая операция могла сохраниться. Изменения существующих записей
также требуют `expected_version`; конфликт версии требует чтения свежей записи.
При исправлении обращения пропущенные необязательные поля сохраняются; явный
`null` очищает поле. Изменённое пожелание по времени пересчитывается от сохранённого
исходного момента, если он известен; старое предположение о дате удаляется.

Исходный текст обращения сохраняется отдельно от извлечённых полей. «Завтра» в
пересланном сообщении считается от `source_occurred_at` и `source_timezone`, а не
от момента обработки. Если исходный момент неизвестен, текст пожелания можно
сохранить без выдуманной точной даты. Даты поручений требуют timezone offset.

## Проверка перед использованием

Backend-проверки покрывают MCP initialization, discovery, read/write, повторный
запрос, ошибки доступа и защиту от чтения/связей другой компании. Чтение заказа
использует отдельную чистую проекцию и не вызывает legacy repair предложений.

Фактическое подключение в аккаунте пользователя, создание custom MCP server,
OAuth callback ChatGPT, установка personal plugin, Android, голос и фото
требуют проверки на реальных клиентских поверхностях после deploy. Наличие
пакета и backend-тестов не подтверждает прохождение этих клиентских проверок.
Для ручной проверки создать неполное обращение, проверить исходный текст и
поля в Manager; создать/изменить/завершить поручение; повторить write с тем же
ключом; отозвать подключение и убедиться в отказе следующего tool call.

Использован текущий формат из официальных руководств:
[пакет плагина](https://developers.openai.com/plugins/build/plugins),
[MCP](https://developers.openai.com/plugins/build/mcp-server),
[авторизация](https://developers.openai.com/plugins/build/auth).

## Manager и напоминания

Быстрое входящее доступно в очереди «Входящие»: достаточно текста. Контакты,
адрес и пожелание по времени можно заполнить позже. Для старой переписки время
не подставляется автоматически; отметка «Текст записан сейчас» задаёт исходный
момент только для нового сообщения. Исправление использует текущую версию.

Поручения доступны по `/manager/tasks`. Напоминание сохраняется в базе и
отображается на странице поручений после указанного времени. Это напоминание
внутри Manager: внешнее уведомление не отправляется. Перенос заменяет прежнее
время; завершение или отмена убирает напоминание. Повторное открытие сохраняет
время, поэтому прошлое напоминание снова появляется сразу.

Отзыв подключения находится в личном профиле `/manager/profile`, в блоке
«Подключения ChatGPT», и доступен владельцу подключения.

## Выпуск и откат

Миграция `f10a2b3c4d5e` после `fe34cd56ef78` добавляет таблицы подключения,
аудита и поручений, а также nullable-поля входящих и версию в `lead`.
Существующие записи получают версию 1. Миграция не квалифицирует обращения,
не создаёт заказы и не требует backfill/provisioning/grants.

Применение выполняется штатным release workflow до активации нового образа.
Проверить health/readiness, продукты и конфигурацию фильтров, затем discovery и
неавторизованный MCP: ожидается 401 с `WWW-Authenticate`.

Для аварийной приостановки MCP установить `CONNECTOR_ENABLED=false` и
перезапустить API. Manager и отзыв grants остаются доступны. Для отката образа
сохранить новую схему и данные. `alembic downgrade` удаляет новые поручения,
подключения и metadata обращений; в production его не выполнять как обычный
откат выпуска.
