# Автосохранение карточки заказа

Карточка заказа в канбане и календаре по умолчанию сохраняет изменения после
700 мс без ввода. Переключатель в шапке запоминает выбор для текущего менеджера
и организации в этом браузере. Кнопка «Сохранить» позволяет сохранить сразу.

Автоматически сохраняются название, адрес и филиал объекта, комментарий,
метки, планирование и исполнители, параметры переговоров и выполнения,
данные ремонта, валютные параметры, товары и услуги активного предложения.
Выбор адреса в подсказке сразу меняет адрес заказа. «Готово» закрывает редактор.
Для юрлица без адреса доступен подбор через существующий сервис подсказок
по названию организации; адрес применяется только после выбора кандидата.

Создание сущностей остаётся отдельным действием: запись платежа, создание
филиала, загрузка вложения, привязка оборудования, изменение общей карточки
клиента и выпуск документа. Условия и параметры конкретного документа
применяются при его создании.

Перед Google-документом или нативным черновиком CRM карточка дожидается
сохранения. При ошибке документ не создаётся, а введённые данные остаются
в карточке. При выключенном автосохранении сначала требуется нажать
«Сохранить». Закрытие карточки с включённым автосохранением также ждёт
сохранения; ошибка оставляет карточку открытой. Закрытие/перезагрузка вкладки
с несохранёнными данными вызывает стандартное предупреждение браузера.
Работа без сети не считается успешным сохранением.

## Границы реализации

- `useOrderAutosave` объединяет частые изменения и выполняет записи
  последовательно. Ожидание записи также учитывает новые правки во время запроса.
- `useOrderDrawerSaving` отправляет изменённые поля, сохраняет снимок именно
  отправленных данных и не затирает новый ввод старым ответом сервера.
  Ответы после смены заказа/пользователя или закрытия карточки не применяются.
- Строки разных вариантов сохраняются с явным `line_proposal_id`.
  Это необязательное поле `PATCH /api/manager/orders/{order_id}` определяет
  вариант даже для пустых массивов после удаления последней строки.
  Оно должно совпадать с `proposal_id` переданных строк. Сервер проверяет
  принадлежность заказу и запрет изменения отправленной/принятой редакции.
- Это очередь записи одной карточки, а не механизм разрешения одновременных
  правок одного поля несколькими менеджерами.

Проверки: `npm run test:components`, `npm run test:ui-logic`, `npm run build`
в `manager_frontend`; серверные регрессии находятся в
`tests/unit/test_order_update_command_service.py`.
