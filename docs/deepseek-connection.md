# DeepSeek в настройках платформы

Откройте **Manager → Настройки → AI-подключение → DeepSeek** под владельцем
или администратором системной платформы. Партнёрские аккаунты не могут читать,
менять, переносить или проверять этот ключ.

## Управление ключом

- **Сохранить** заменяет ключ на сервере. Пустое поле сохраняет существующий
  ключ; после успешного сохранения поле очищается. API возвращает только статус.
- **Перенести текущий ключ** явно переносит `DEEPSEEK_TOKEN` из окружения
  обслуживающего API-узла в зашифрованную запись. Ключ не проходит через браузер.
  Уже сохранённый ключ этим действием перезаписать нельзя.
- **Включить / Отключить** непосредственно переключает использование DeepSeek.
- **Удалить ключ** удаляет сохранённый секрет и отключает подключение. Пустая
  запись остаётся как запрет автоматического возврата к ключу из окружения.
  Повторный перенос возможен только отдельным явным действием администратора.
- **Проверить запрос** отправляет короткий синтетический JSON-запрос с лимитом
  16 выходных токенов. Он может расходовать баланс и доступен также для
  отключённого подключения; обычные рабочие запросы при этом остаются отключены.

До первого сохранения существующий ключ окружения продолжает работать. После
сохранения, переноса, отключения или удаления источником всегда служат настройки.
Ошибки базы или расшифровки никогда не включают резервный ключ окружения.
Каждый новый запрос читает актуальную запись через отдельную короткую сессию;
смена ключа действует на обоих API-узлах без перезапуска. Уже начавшийся запрос
может завершиться со старым ключом.

Договоры, контент каталога, реквизиты, разбор писем, тендерных документов и
серверные AI-функции staff-бота используют этот источник. Текущие модели
`DEEPSEEK_MODEL` и `CONTRACT_REVIEW_MODEL` не изменены. Выбор другого провайдера
или модели в отдельном запуске является следующим этапом, а ZAPRO.SU остаётся
самостоятельным подключением.

## Безопасность и партнёры

Секрет хранится в `deepseek_connection` через общий
`INTEGRATION_CREDENTIAL_KEYRING_JSON` с отдельным контекстом DeepSeek; ключи
шифрования остаются вне базы. Запись входит в проверки доступности credentials
и reviewed rewrap. Пустая запись после удаления не считается credential.
Изменения настроек регистрируют имя администратора и действие, без ключа.

Партнёрские Manager-запросы к платным AI-действиям (договоры, реквизиты,
тендерный анализ, акт дефекта, контент каталога) запрещены до отдельного
подключения платного доступа. Просмотр и обычные операции CRM остаются доступными
в границах партнёрского аккаунта. Подписки, учёт расхода и списание денег этот
этап не реализует. Активный staff-бот уже ограничен системным аккаунтом.

При компрометации замените ключ в Manager и отзовите старый в кабинете DeepSeek.
Удаление секрета у нас не отзывает его у провайдера.

## Выпуск и перенос на production

Миграция создаёт только таблицу, без копирования секретов и активации партнёров.
Выпустите PR через green CI и обычный [процесс деплоя](deployment.md), затем
проверьте обязательные smoke endpoints и
[доступность credentials](integration-credential-keyring-runbook.md).

Перенос начинается с read-only проверки: рабочий узел — Patroni primary,
источник — `environment`, ключ есть, общей записи пока нет, общий keyring
доступен. После проверки выполните явный импорт под системным owner/admin;
не передавайте ключ в командной строке, сообщениях или логах. Проверьте
`source=settings`, `configured=true`, `enabled=true`, чтение на обоих узлах
и credentials health. Не запускайте проверку реального договора для smoke.

После подтверждённого переноса старый `DEEPSEEK_TOKEN` можно отдельно убрать
из защищённого окружения обоих узлов через проверенную процедуру обслуживания.
Рабочие запросы уже используют базу, даже пока значение остаётся в окружении.
Откат на старый образ возвращает управление к окружению: после ротации ключа
используйте только образ с поддержкой настроек либо отдельно согласуйте rollback.
