# Записи звонков из личного Google Диска

Результат #1086 — отдельное личное подключение и выключенный по умолчанию
конвейер: выбранная папка → законченная версия записи → расшифровка →
предлагаемые действия → явное сохранение одного действия во входящие/поручения.
Загрузка в очередь ещё не означает успешную обработку. Обычный ручной ввод
входящих и поручений работает независимо от этой интеграции.

## Наблюдаемое состояние и граница пилота

9 октября 2026 проверены только метаданные личного Google Диска через подключённый
пользовательский connector: папка «Записи звонков» существует, список файлов
доступен, Shared Drive отсутствует. Имена Samsung имеют шаблон
`Вызов <подпись контакта>_YYMMDD_HHMMSS.m4a`; Drive сообщает MIME `video/3gpp`,
наблюдаемые размеры примерно 0,7–3,2 МБ. Подпись контакта не доказывает личность
или телефон; `modifiedTime` не доказывает начало звонка.

Доступ connector сам по себе не доказывает OAuth grant приложения. Личное
подключение и выбранная папка приложения подтверждены на сервере 9 октября 2026.
Пилот ограничен одной согласованной записью; автоматическая проверка папки
выключена. Результат реального пилота фиксируется в #1086 отдельно от
проверок с имитациями провайдеров. Имитированные ответы проверяют состояние,
повторы и права, но не качество распознавания реального разговора.

## Настройка и проверка одной записи

1. В Manager открыть «Записи звонков» (`/manager/calls`) под своей staff-учётной
   записью. Владелец компании не получает доступ к чужим личным записям.
2. Подключить Google отдельно для звонков. Запрашивается только
   `https://www.googleapis.com/auth/drive.readonly`: существующий документный
   `drive.file` не открывает загруженные Samsung файлы. OAuth client использует
   существующий серверный `client_secret.json`; добавить redirect
   `/api/manager/call-recordings/oauth/callback` на HTTPS origin Manager.
   `CALL_RECORDINGS_OAUTH_REDIRECT_URI` при явной настройке должен точно совпадать
   с этим адресом. Personal Drive поддерживается без Shared Drive.
3. Выбрать существующую папку по ссылке. Подключение и выбор папки не включают
   автоматическую проверку. Для реальной обработки оператор отдельно разрешает
   `CALL_RECORDINGS_ENABLED=true`; штатный `SchedulerService` потребляет очередь
   только при этом флаге и включённом планировщике приложения.
4. Для согласованного пилота вставить ссылку на **одну** запись и выполнить две
   проверки с интервалом не менее минуты. Пустое поле проверяет ограниченную
   страницу папки. Файл должен присутствовать непосредственно в выбранной папке.
5. Обновить список, дождаться «Готово к разбору», проверить исходную запись,
   расшифровку и каждое предлагаемое действие. Неизвестное время/телефон можно
   уточнить вручную; затем явно повторить незавершённый этап для обновления
   предложений без нового платного извлечения.
6. Сохранить конкретное отредактированное входящее или поручение. Для входящего
   отдельный переключатель явно раскрывает также сохранение связанного поручения
   «Уточнить адрес / созвониться перед выездом». Заказ, подтверждённый выезд,
   изменение существующих фактов и отправка клиенту не выполняются.

Для дальнейшей обработки пользователь отдельно включает прямой переключатель
автоматической проверки выбранной папки. Это согласие на обработку новых файлов
из всей этой папки; личные и семейные разговоры требуют заранее выбранной границы
источника. Выключение останавливает polling; отключение Google удаляет локальную
credential и блокирует дальнейшие этапы. Сохранённый материал/действия остаются.

## Провайдеры, устойчивость и лимиты

В настройках личной папки выбирается провайдер: `google_batch` или `groq`.
Выбор сохраняется вместе с папкой и не включает автоматическую проверку.
Провайдер и модель фиксируются перед первым распознаванием записи; уже
отправленное задание и успешный транскрипт сохраняют исходный провайдер.
Metadata-only revision с одинаковыми байтами сохраняет успешные платные
checkpoints и сведения о применённом провайдере.

Google использует Speech-to-Text v2, модель `chirp_3`, язык `ru-RU` и
`DYNAMIC_BATCHING`. Это дешёвый отложенный режим; результат может появиться
в течение 24 часов. Нужны серверные настройки
`CALL_RECORDINGS_GOOGLE_CREDENTIALS_FILE`,
`CALL_RECORDINGS_GOOGLE_PROJECT_ID` (canonical project number из operation name),
`CALL_RECORDINGS_GOOGLE_BUCKET`, `CALL_RECORDINGS_GOOGLE_LOCATION` (`eu` или `us`)
и `CALL_RECORDINGS_GOOGLE_MODEL`. Credential — явно настроенный service account;
доступ личного Drive остаётся отдельным. Speech API должен быть включён, а
приватный bucket и speech service agent должны иметь нужный доступ в проекте.

В bucket временно помещается только нормализованное аудио под непрозрачным
идентификатором. Обязательные настройки: public access prevention, uniform
bucket access, lifecycle Delete с возрастом два дня, soft delete выключен.
Single-file batch возвращает inline result; транскрипт не записывается в GCS.
После закрепления транскрипта приложение удаляет временное аудио; lifecycle
страхует аварии/недоступную очистку. Это временный input bucket, а не архив.

Номер Google operation закрепляется в PostgreSQL перед ожиданием. Состояние
`waiting_transcription` означает обычное ожидание, а не ошибку. Раз в пять минут
worker проверяет то же задание GET-запросом без новой отправки аудио и без
расходования лимита неудачных/платных попыток. Ожидание переживает перезапуск;
через 26 часов без результата карточка требует ручного разбора. Настройки
project/location/bucket для находящихся в ожидании заданий менять нельзя.

Groq сохраняет существующий HTTP-адаптер с отдельными настройками звонков:
`CALL_RECORDINGS_TRANSCRIPTION_API_URL`, `CALL_RECORDINGS_TRANSCRIPTION_MODEL`
и `CALL_RECORDINGS_TRANSCRIPTION_API_KEY`. Флаг/ключ штатного бота не запускает
звонки. Наличие credential означает локальную настроенность, а не доказанный
доступ к модели; IAM, billing и ошибки провайдера проверяются реальным заданием.

Структурирование использует существующий platform DeepSeek transport,
его текущий `DEEPSEEK_MODEL` и управляемое в Manager подключение. UI показывает
выбранный провайдер, модель, readiness и незавершённый этап. Сохранение обычных
входящих/TODO не вызывает AI.

Контракты Google: [batchRecognize](https://docs.cloud.google.com/speech-to-text/docs/reference/rest/v2/projects.locations.recognizers/batchRecognize),
[тарифы](https://cloud.google.com/speech-to-text/pricing).

| Ограничение | Значение |
| --- | --- |
| Исходная запись | 10 МБ, 1–600 секунд |
| Нормализованная аудиодорожка | mono PCM WAV, 16 кГц, до 20 МБ |
| Poll | До 5 файлов, cursor pagination |
| Новые версии на личное подключение | До 20 за скользящие 24 часа |
| Worker batch / автоматические источники за проход | До 3 / до 3 |
| Стабильность | Две наблюдаемые версии, интервал ≥60 секунд; modifiedTime старше 60 секунд |
| Попытки этапа | До 3, ручной retry лимит не сбрасывает |
| Outbox / lease | До 9 неудачных claims; обычные проверки готовности Google не расходуют лимит; lease 300 секунд с heartbeat и token fencing |
| AI вызовы | HTTP-операция речи ≤60 секунд; ожидание Google ≤26 часов; DeepSeek ≤50 секунд, ≤3000 output tokens |

Drive file ID, revision/version, размер и MD5 идентифицируют источник. После
скачивания проверяются размер/MD5 и повторно метаданные. Действительное аудио
проверяет ffprobe; `video/3gpp` не отвергается только по MIME. ffmpeg извлекает
только аудиодорожку из ограниченного контейнера. Инструменты уже входят в образ.

Успешные стадии сохраняются в PostgreSQL: нормализованное аудио до успешной
расшифровки, затем transcript, затем structured extraction и предложения.
После речи временный аудиокэш очищается; исходник остаётся по Google-ссылке.
Изменённая версия создаёт новую карточку и сохраняет старый материал. Для
идентичных байтов metadata-only revision переиспользует успешные платные стадии.
Одинаковая grounded цитата/тип действия в той же записи ссылается на долговечный
receipt принятия независимо от версии. Новая цитата остаётся новым предложением
на явный разбор. Никакой версии не разрешено автоматически применять действия.

Результат платного запроса, полученный прямо перед аварией процесса и ещё не
закреплённый в БД, может потребовать повторной оплаты: speech/DeepSeek не дают
здесь транзакционной гарантии exactly-once. Сохранённые checkpoints повторно
не вызываются; лимит попыток ограничивает эту неопределённость.

Просроченный lease восстанавливается другим worker, старый token не может
сохранить результат. Временный сбой планирует ограниченный backoff; отказ OAuth
останавливает источник и показывает необходимость переподключения. После
переподключения явно повторить карточку: checkpoint речи/разбора сохраняется.
Нечитаемое аудио, изменившийся файл или исчерпанный лимит требует ручного разбора;
повтор не снимает лимиты. Сообщения провайдеров/транскрипты/ключи не записываются
в error logs; сохраняются безопасный код и название этапа.

## Происхождение и права

Credential зашифрована существующим keyring в отдельном контексте звонков и
envelope tenant/staff/storefront. Pending OAuth state одноразовый, на 10 минут;
callback повторно проверяет auth version, живого сотрудника, роль и членство.
Каждый read/write и checkpoint проверяет живые права. Фоновый источник хранит
доверенного автора, но его сохранённый ID не обходит отзыв прав. Demo read-only
не допускает настройки/обработку/adoption. HTTP list имеет `limit <=100`.

Samsung filename с валидной датой даёт исходное время в `Europe/Minsk`, ручной
aware timestamp — отдельный источник. Неизвестное время остаётся неизвестным;
день обработки и Drive modifiedTime не служат fallback. Относительная дата
обязана присутствовать в grounded цитате и вычисляется от исходного разговора.
«Завтра утром» сохраняет желаемый день и исходную формулировку с требованием
уточнить время; в карточке день показан отдельно, поле точного времени пустое.
У входящего сохраняется `date_precision=date`, явное ручное время даёт `datetime`.
Принятая карточка показывает сохранённый день, даже после исправления времени
исходного звонка; date-only поручение не получает выдуманный срок в 00:00.
Телефон должен присутствовать как отдельный числовой фрагмент речи либо быть
явно выбран вручную. Числа разных цен/дат/ID не складываются в телефон.
Приложение не получает Android call log, телефонную книгу или переписку.

Transcript — недоверенные данные. Structured extraction ограничена typed JSON,
цитаты проверяются по исходному тексту, факты/даты остаются предложениями.
Adoption одной карточки и shared Incoming/PersonalTask command с audit и
долговечным source receipt коммитятся атомарно. Повтор с изменённым payload той
же принятой карточки, включая новые версии Drive, возвращает 409 и требует
редактировать сохранённое входящее/поручение; одинаковый повтор принятого действия
возвращает сохранённую ссылку. Обычный 30-дневный command replay horizon не
удаляет долговечный receipt звонка. Выгрузка `.txt/.json` в Drive не реализована:
readonly scope и состояние в Kitlane достаточны для текущей границы.

API: `/api/manager/call-recordings` — connection/status/OAuth, folder, bounded
poll, list/detail, metadata, retry и explicit adoption. Схемы и ошибки описаны
у маршрутов и в [OpenAPI](../openapi.json); входящие/поручения используют
[общие authenticated команды](incoming-triage-workspace.md).
