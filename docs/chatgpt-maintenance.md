# Kitlane / ChatGPT: ограниченный сценарий ТО

Срез [#1087](https://github.com/mvnby/air-api/issues/1087) использует выпущенный
домен [замечаний, актов и предложений ТО](equipment-maintenance.md).
MCP-каталог версии 1.1 содержит 28 инструментов: прежние 15 операций
обращений/поручений и 13 адаптеров ниже. Это серверный контракт; конкретный
релиз подтверждается PR, CI и deploy, клиентский пилот — отдельным результатом.

## Инструменты и границы

| Инструменты | Результат |
| --- | --- |
| `list_equipment`, `get_equipment`, `list_equipment_history` | Реестр по подтверждённому клиенту/объекту, оборудование и доступная история работ; чтение ничего не создаёт |
| `list_maintenance_findings`, `get_maintenance_finding` | Замечания по одному ТО, оборудованию либо клиенту/объекту; текущая версия, исходник, ревизии и ID фото |
| `create_maintenance_finding`, `update_maintenance_finding` | Факты осмотра и рекомендация, также на CLOSED ТО; оборудование может быть неизвестным; исправление требует `expected_version` |
| `upload_maintenance_finding_photo` | Один явно переданный файл ChatGPT сохраняется приватно у конкретного замечания |
| `get_maintenance_finding_photo` | Приватное изображение возвращается inline через текущий OAuth/MCP; storage URL не выдаётся |
| `list_maintenance_defect_acts`, `prepare_maintenance_defect_act` | Чтение подготовок и явная подготовка native draft по выбранным актуальным ревизиям и подтверждённому юридическому лицу |
| `list_maintenance_offers`, `prepare_maintenance_offer` | Сохранённые коммерческие версии и реальные активные варианты продолжения с ID строк/ценами; явная фиксация состава и ревизий в draft |

Read требует `kitlane:read`; пять write-инструментов — дополнительно
`kitlane:maintenance:write`. Старый grant не получает новый scope автоматически:
для записи ТО пользователь подключается снова и явно разрешает его. Actor,
tenant и storefront определяются текущим OAuth; права, исходный объект и
продолжение проверяются перед выполнением и перед replay. Служебный bot secret
не используется. Во входных аргументах нет actor/tenant или произвольного HTTP/SQL.

Общий [AuthenticatedCommandService](../services/authenticated_command_service.py)
сохраняет actor/channel/operation/resource, receipt и доменную запись атомарно.
Идентичный ключ/payload возвращает прежний ID и `replayed=true`; изменённое
содержание с тем же ключом либо устаревшая версия дают 409. После потери ответа
повторяется прежний ключ, а не создаётся новая команда. Компактная квитанция
не копирует всю растущую историю ревизий. Источник замечания — `chatgpt_maintenance`.

`list_maintenance_offers` возвращает только существующие предложения продолжения
и сохранённые цены обычных строк, без внутреннего cost. `prepare_maintenance_offer`
проверяет полный актуальный состав выбранного варианта и версии замечаний.
Если продолжения, состава или цен ещё нет, их нужно подготовить в Manager;
адаптер не подставляет тариф, цену или общую сумму. Варианты и коммерческие
версии читаются ограниченными страницами `limit`/`offset`.
Состав более 100 строк возвращается как `lines_complete=false` без частичного
списка строк; такой вариант обрабатывается в Manager.

В Manager остаются редактирование состава/цен, выбор настроек юридического лица,
preview/редактирование документа, выпуск/подписание/доставка, фиксация явного
согласия и переход к исполнению, расписание/бригада, подтверждение выполненного
ремонта и новая REPAIR history. Согласие и текст рекомендации не подменяют
выполненную работу. Подготовка акта может создать/reuse NEGOTIATION продолжение,
но не меняет исходное закрытое ТО, его документы, выполненные работы или план ТО.
Новые внешние команды этих оставшихся операций требуют отдельного контракта.

## Передача и чтение приватного фото

Используется поддерживаемый [ChatGPT file input](https://developers.openai.com/plugins/reference#file-apis):
у инструмента `_meta["openai/fileParams"]=["file"]`; top-level `file` требует
`download_url` и `file_id` и объявляет необязательные `mime_type`/`file_name`.
Наличие такой схемы не доказывает, что конкретный пользовательский Android-клиент
уже передал файл. Не заменять этот вход произвольной ссылкой или base64 текста.

Список `CONNECTOR_CHATGPT_FILE_HOSTS` по умолчанию пуст. Загрузка сообщает
`invalid_file` с направлением в Manager, пока оператор не подтвердит точный
hostname реальной выдачи ChatGPT в клиентском пилоте. Официальный контракт не
фиксирует hostname; предполагать его по названию CDN нельзя.

Порядок включения: передать тестовое фото из существующего личного подключения,
зафиксировать только origin/hostname фактического file input, сверить владельца
источника с официальным клиентским путём, затем установить JSON-список точных
подтверждённых hostnames в `CONNECTOR_CHATGPT_FILE_HOSTS` и перезапустить API.
Не сохранять подписанный URL/query, токены или бизнес-фото в отчёт/лог. Пустой
список отключает вход; wildcard/suffix, URL и IP вместо hostname не допускаются.
Не расширять список ради произвольных внешних картинок.

Источник требует HTTPS без credentials/port/fragment, точного разрешённого host,
только публичных DNS-адресов и закрепления проверенного адреса для соединения.
Redirects и environment proxies отключены. DNS ждёт не более 5 секунд, загрузка
15 секунд; тело ограничено меньшим из 20 MiB и лимита приватных вложений, даже
без Content-Length. Изображение декодируется и проверяется; принимаются JPEG,
PNG и WebP до 20 миллионов пикселей, MIME должен соответствовать байтам. Другие форматы загружаются
через Manager по его собственному контракту.

При timeout/истечении временной ссылки сохраняются `file_id`, metadata и
`idempotency_key`; ChatGPT может обновить только `download_url`. Временный URL
не входит в fingerprint/receipt/audit. Новый `file_id` с прежним ключом конфликтует.
Оригинал, preview и связь с замечанием используют существующее приватное хранилище.
Read проверяет, что активное вложение принадлежит именно доступному замечанию,
и возвращает проверенный bounded preview как MCP ImageContent; общего file-browser
или публичной ссылки нет.

## Проверка и передача

[Серверный consumer test](../tests/integration/test_connector_mcp_maintenance.py)
проверяет реальный OAuth/MCP/PostgreSQL путь, доступ и отзыв/понижение роли,
чужие tenant/storefront/ID, replay, конкурентную команду, changed payload,
stale version, commit acknowledgement loss и rollback при ошибке receipt.
[File tests](../tests/unit/test_connector_files.py) проверяют official schema,
запрет URL/DNS/redirect/proxy, pinned resolver, размер и действительное изображение.
Доменная семантика и native draft остаются под проверками #1085.

Для реального пилота после release обновить discovery/reconnect существующего
подключения, получить согласие на maintenance scope, выбрать тестовый заказ ТО,
сохранить факт без выдуманного диагноза и передать тестовое фото. Проверить фото
в Manager и через MCP, prepare draft/offer с реальными источниками, повтор и отзыв.
Отдельно записать результаты ChatGPT web и Android, диктовки и полноценного Live,
а также экранного подтверждения write. Серверные тесты не доказывают этих результатов.
[#1087](https://github.com/mvnby/air-api/issues/1087) остаётся открытой до
прохождения клиентских критериев. Drive ingestion, отправка писем и публичный
каталог плагинов в этот срез не входят.
