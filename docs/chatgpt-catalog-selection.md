# Kitlane / ChatGPT: подбор оборудования и документы

Расширение [#1087](https://github.com/mvnby/air-api/issues/1087) добавляет четыре
инструмента к [существующему MCP](chatgpt-connector.md). Каталог версии 1.2
содержит 32 инструмента. Это серверный контракт; клиентское discovery и новое
согласие проверяются после выпуска.

## Подбор для физлица

`select_catalog_products` требует класс охлаждения либо площадь комнаты.
Количество, инвертор, минимальная температура обогрева, Wi-Fi, бренд и бюджет
задаются явно. `budget_scope=per_unit` означает бюджет одного кондиционера,
`total` — всей указанной партии оборудования. Монтаж в этот бюджет не включён.
При неизвестной основе бюджета для нескольких единиц skill уточняет её.

Без бюджета возвращаются до трёх разных моделей в нижнем, среднем и верхнем
уровнях различных публичных цен подходящего каталога. При одинаковых ценах
выбирается один вариант на уровень. Верхняя цена не является доказательством
премиального качества. С бюджетом подбор ищет подходящие альтернативы разных
брендов во всём допустимом каталоге; если брендов меньше, возвращает два или один
вариант. Фильтры не ослабляются автоматически; отсутствие результата объясняется.

Результат содержит актуальную цену BYN, модель, бренд/серию, только известные
базовые характеристики, количество и стоимость оборудования для каждого
варианта отдельно. `message_text` — готовый обычный текст со ссылками для
копирования в WhatsApp, Viber или Telegram. Альтернативы не суммируются.
Наличие не означает обещанную дату доставки. Wi-Fi под модуль отличается от
встроенного. Минимальная рабочая температура не доказывает мощность в мороз.

`get_catalog_product` проверяет конкретную модель. Видимость и цена определяются
витриной текущего OAuth actor: опубликованные товары канонической витрины либо
реальные опубликованные предложения и действующие grants другой витрины.
Чужая цена не заменяется общей. Закупочные цены, маржа, поставщики и credentials
не выходят в ответ. Ссылки другой витрины используют её подтверждённый домен;
при отсутствии домена ссылка остаётся неизвестной.

## КП и счёт для юрлица

`list_catalog_document_issuers` возвращает активные юридические лица текущей
компании. `prepare_catalog_document` принимает подтверждённые `order_id`,
`customer_id`, `legal_entity_id`, дату, тип `offer`/`invoice`, необязательный
шаблон и выбранные product ID/количества/ожидаемые цены.

Команда работает с существующим заказом в переговорах и сохранённым клиентом
типа юрлицо или ИП. Она не создаёт клиента или заказ. Для счёта сначала выбирается
один вариант: альтернативные покупки не складываются. Несколько формальных КП
создаются отдельными явными командами. Монтаж и услуги этим срезом не добавляются.

Сервер заново проверяет область доступа, связку заказа/клиента, активного
эмитента, доступные товары и коммерческие цены. Изменившаяся цена даёт конфликт
до сохранения. Сервер создаёт отдельное невыбранное предложение и нативный
черновик документа из его строк. Старые предложения, тип клиента и документы
сохраняются. Состав и snapshot не включают другие варианты заказа.

Предложение, документ, audit и receipt сохраняются одной транзакцией. При
отсутствии шаблона/реквизитов операция не оставляет частичного предложения.
Идентичный повтор возвращает прежние ID; другой payload с тем же ключом даёт
конфликт. Доступ проверяется и перед replay. Подготовка не выпускает документ,
не резервирует официальный номер, не подписывает и не отправляет его.
Результат содержит ID и рабочую ссылку Manager для обычной проверки и выпуска.

Чтение требует `kitlane:read`; подготовка — новое отдельное согласие
`kitlane:catalog:write`. Старые grants не расширяются. Для новых инструментов
обновить discovery/подключение и получить это согласие. Миграция и backfill
не нужны. Отключение MCP и откат образа следуют
[общей инструкции](chatgpt-connector.md#выпуск-и-откат).

## Приёмка

- «Три варианта 12 для обогрева до −20» — разные цены, все соответствуют фильтрам.
- «Два кондиционера 12, до 3000 за комплект, разных брендов» — каждый вариант
  содержит две единицы и укладывается в общий бюджет; монтаж указан отдельно.
- Мало брендов/нет совпадений — честный неполный результат, без выдуманных моделей.
- Скопированный текст содержит обычные ссылки и понятные цены каждого варианта.
- «Подготовь КП/счёт по выбранному варианту для этого заказа» — отдельное
  предложение и нативный draft; цена, количество и строки проверены.
- Повтор/конкуренция/потеря ответа не создают дублей; ошибка документа откатывает
  предложение; старый scope и чужая компания/клиент/эмитент не дают запись.

Проверки: [подбор](../tests/integration/test_connector_catalog_selection.py),
[документы и MCP](../tests/integration/test_connector_catalog_documents.py).
Android/Live, фактический клиентский discovery и копирование сообщений проверяются
отдельно; серверные тесты не являются подтверждением этого пилота.
