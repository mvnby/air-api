# B2C: продажа с монтажом в два этапа

Двухэтапный монтаж — опция существующего `b2c_supply_installation_act`,
а не отдельный тип заказа или документа.

В форме включается «Монтаж в два этапа» и вводится сумма к оплате за первый
этап. Общая сумма берётся из строк выбранного предложения. Например,
при общей сумме 3 140 BYN и первом этапе 3 000 BYN остаток равен 140 BYN.
Сумма первого этапа должна быть положительной и меньше общей суммы;
копейки рассчитываются точно. Сервер повторно проверяет сумму по выбранным
строкам при создании черновика.

Первый этап: наружный блок, штробление и коммуникации. Второй: внутренний
блок, подключение и пусконаладка после ремонта по согласованию сторон.
Переключатель состава первого этапа позволяет оставить в нём только
штробление и коммуникации: тогда установка наружного блока автоматически
переходит во второй этап. `installation_outdoor_unit_in_first_stage` по
умолчанию равен `true`, сохраняя поведение ранее созданных запросов.
Подпись на таком заказе-акте подтверждает приёмку только первого этапа.
Остаток оплачивается после второго этапа. График не регистрирует получение
денег: фактические оплаты по-прежнему вносятся через платежи заказа.

Действие «Создать замену» сохраняет уже введённые условия, если тип документа
остаётся прежним: два этапа, состав работ, первый платёж и данные оборудования.
При переходе на другой тип документа условия сбрасываются к его значениям
по умолчанию.

## Данные оборудования

`GET /api/manager/document-system/orders/{order_id}/consumer-defaults`
принимает `proposal_id` и `issue_date`, проверяет доступ к заказу в текущей
организации и витрине. Если в выбранном предложении один артикул
оборудования, бренд и модель берутся из каталога. Несколько единиц одного
артикула допустимы; при неоднозначном составе марка и модель остаются пустыми.
Серийный номер всегда вводится вручную.

Гарантия: политика конкретного товара → серии → бренда (с учётом срока
действия политики), затем характеристика товара `warranty_months`, затем
36 месяцев. Общий срок продавца не меняет этот B2C fallback. Ручные значения
сохраняются; `0` означает не указывать договорную гарантию. Гарантия на работы
сохраняет настройки продавца. Сервер также определяет отсутствующие значения
при создании черновика. Данные попадают в неизменяемый снимок документа.

## Шаблон и выпуск

Версия шаблона должна поддерживать условия `installation.two_stages` и
`installation.single_stage`, а также поля `installation.first_stage_amount`,
`installation.remaining_amount`, `installation.first_stage_works`,
`installation.second_stage_works`, `installation.second_stage_due`.
Черновик с двумя этапами блокируется, если выбран старый шаблон без этих полей.

Пакет `config/native_document_template_bundles/mvn-b2c-installation-v4.json`
обновляет только шаблон поставки и монтажа. Применять через обычные `plan` и
`apply` из [инструкции пакетов](native-document-template-bundles.md), с
проверенным SHA-256 приватного DOCX. Полный пакет `mvn-2026-v1.json` также
ссылается на новую версию, чтобы повторный onboarding не откатывал её.
В CRM v4 удалены три пустых абзаца после подписей, создававшие лишнюю пустую
страницу при заполнении реальными строками заказа. Текст этапов подставляется
из снимка; обе ветки проверены на реальном составе заказа без его изменения.
Исторические шаблоны и уже созданные документы остаются неизменными;
для новых условий создаётся новый черновик.
