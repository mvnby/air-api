# YML-feed для Яндекс Бизнеса

## Публичный URL

Production feed доступен без авторизации:

`https://api.mvn.by/api/v1/feeds/yandex-business.yml`

Яндекс забирает XML по этому адресу. Feed создаётся при каждом запросе из
актуального состояния базы, поэтому физический YML-файл и cron не нужны.
Абсолютные ссылки строятся из `PUBLIC_SITE_URL` (production default:
`https://mvn.by`).

Авторизованный Manager endpoint
`/api/manager/yandex-business/price-list.yml` использует тот же генератор и
остаётся доступен для ручного скачивания.

## Редакционные категории

1. Создайте и опубликуйте товарную подборку в Manager.
2. Добавьте placement:
   - `surface`: `yandex_business`;
   - `slot`: `categories`.
3. Включите placement и задайте `position`.

Подборки разрешаются штатным resolver: поддерживаются ручной, автоматический и
гибридный режимы, pinned items, правила, расписание, `min_items`, `max_items` и
fallback. Порядок определяется по `position`, затем по ID placement.

Если один товар подходит нескольким подборкам, его забирает первая подборка.
Один товар не может находиться одновременно в нескольких категориях Yandex.
Остальные товары группируются по брендам, а товары без бренда попадают в
«Другие модели». После товарных категорий выводятся активные услуги с
положительной ценой.

Пустые, выключенные, неопубликованные и находящиеся вне активного временного
окна категории в XML не создаются.

## Изображения и описания

В `<picture>` попадает только готовый вариант `yandex_feed` основной картинки.
Он создаётся существующим product-media pipeline и хранится в настроенном
local/R2 storage рядом с остальными вариантами:

- JPEG, quality 85;
- холст 800×800 px;
- исходные пропорции без обрезания;
- белый фон, включая корректное наложение прозрачного PNG;
- EXIF orientation, sRGB и удаление лишних метаданных;
- content-addressed имя и immutable cache.

WebP не переименовывается и не конвертируется во время запроса YML. Если
варианта нет или его генерация завершилась ошибкой, offer остаётся в feed без
`<picture>`, а причина появляется в отчёте качества.

После первого deploy выполните безопасный идемпотентный backfill. По умолчанию
команда работает в dry-run:

```bash
python3 scripts/backfill_yandex_feed_images.py --limit 100
python3 scripts/backfill_yandex_feed_images.py --execute --limit 100
```

Повторяйте execute с `--after-product-id <next_after_product_id>`, пока
`inspected` не станет равен нулю. Уже актуальные варианты не преобразуются
повторно. Для точечной проверки доступны `--product-id`, а `--force` нужен
только при намеренной пересборке.

Legacy-товары со сторонним `main_image` при execute сначала проходят общую
SSRF-защищённую загрузку MediaLibrary. Исходник сохраняется как `original` в
настроенном product-media storage, но `Product.main_image` и URL изображения
на сайте не изменяются. Для feed-варианта разрешены старые исходники до 70 MP;
общий лимит остальных product-вариантов остаётся 40 MP.

Описания преобразуются в plain text: удаляются `style`, `script`, `noscript`,
HTML-разметка и ведущие CSS-блоки, декодируются entities, после чего текст
нормализуется и ограничивается по длине.

## Отчёт качества

Авторизованный endpoint `/api/manager/yandex-business/quality-report` использует
тот же builder, что публичный и скачиваемый YML. Он возвращает:

- число offer и offer с картинками;
- заполненность редакционных категорий;
- категории, где меньше трёх исправных картинок;
- товары без картинки;
- ошибки генерации `yandex_feed`;
- конфликты, когда товар входит более чем в одну редакционную подборку.

При конфликте действует first-match-wins по порядку placement. Конфликт не
дублирует offer и не останавливает генерацию.

## Проверка

Откройте публичный URL в браузере или используйте действия «Скачать YML» и
«Скопировать ссылку feed» в разделе товаров Manager. После изменения состава,
порядка или расписания подборок повторный запрос сразу формирует новый XML.
