Подборки должны стать удобным инструментом управления товарными блоками для владельца и партнёров Kitlane. Основа дизайна: рабочий процесс варианта A Stitch, мобильные карточки и визуальная иерархия B. Экспорт используется как референс, реализация — нативная для проекта.

## Результат
- Список отдельно от редактора; URL открывает выбранную подборку; полный читаемый товар, мобильная навигация без лишних уровней.
- Товары / Описание / Размещения, ручные и автоматические правила, закрепление и перестановка, реальные исключения и предпросмотр.
- Подборка задаёт состав; размещение задаёт место и формат. Статус публикации отдельно от наличия мест показа.
- Единое атомарное сохранение полей, товаров и размещений. До сохранения правки локальные. Без фиктивного автосохранения и отдельных серверных версий черновика.
- Форматы размещения: слайдер, сетка, плитки, один товар; лимит и число колонок; включение прямым кликом; расписание.
- Известные места: home/featured_products (совместимость), home/after_featured, home/product_of_day, catalog/before_products, catalog/after_products, article/{slot}.
- Повторное использование существующего resolver, правил доступности, расписания, минимума и резервной подборки; отсутствие подходящих товаров скрывает блок.
- Ежедневная ротация одиночного товара по UTC: несколько daily-подборок одного места дают одну выбранную; обычные размещения сохраняются.
- Статьи сейчас MDX: готовый импортируемый компонент и код вставки из Manager, актуальные данные по API без пересборки статьи. Полный CMS вне объёма.

## Разделение работы
1. API (Astra high): совместимое расширение контрактов/миграция, атомарная команда workspace, resolver/preview, изоляция арендаторов, тесты.
2. Manager (Terra medium, финальная интеграция и проверки Sol high): список/редактор, состав/правила, мобильная компоновка, URL/несохранённые изменения, тесты.
3. Витрина (Terra medium): переиспользуемый блок, главная/каталог/MDX, актуализация и форматы, тесты.
4. Координатор: редактор размещений, договорённости API, визуальная приёмка, интеграция, публикация PR и проверка CI.

## Приёмка
- Ширины 360/390 и 1440 px: нет горизонтального переполнения; названия и основные действия читаемы.
- Одна подборка в нескольких местах имеет разные форматы; существующие home-подборки продолжают работать.
- Ошибка сохранения не оставляет частично изменённую опубликованную подборку.
- Черновик/публикация/выключенное размещение/расписание/пустой результат различимы.
- Добавление, замена, порядок, закрепление, автоматический состав и причины исключений проверены.
- Применение настроек не снимает tenant/permission ограничения.
- Миграция, OpenAPI, сгенерированный клиент, релевантные backend/Manager/web проверки проходят.
- PR в air-api и mvn-web связаны, API совместим со старой витриной; merge только после зелёного CI, затем штатная проверка релиза.

Вне объёма: новый конструктор страниц/CMS, выдуманная аналитика, изменения коммерческих данных, backfill или ручные изменения production.
